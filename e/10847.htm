中文翻译

规则

规则用于确保内部指南中参数有效范围的应用和遵守。这通常涉及输入值、计算值的最大和最小限制，以及这些值之间的关系，例如长度/宽度比、长度/直径关系，甚至模数与中心距之间的关系。

这些规则通过存储在 module.rls 文件中进行定义，其中 module 表示计算模块的内部标签，例如 Z012 表示圆柱齿轮副。

这些规则分为两类：一类是在计算执行前必须满足的规则，另一类是在计算后必须检查的规则。如果违反了某条规则，相应的提示信息可以显示。对于在计算前必须检查的规则，还可以将变量设置为常量或计算值。

可以使用以下语句：

precalc：表示在进行计算前必须检查的规则的开始。

postcalc：表示在进行计算后必须检查的规则的开始。

assert(Condition)：用于校验条件。该条件通常是比较表达式，比较式左右两侧均可包含计算。

action msg Message：若前一个 assert 条件未满足，则输出该消息。消息可像报告模板一样包含变量。

action set Assignment：若前一个 assert 的 条件未满足，则执行赋值。赋值可以是一个常量，也可以像报告模板那样由变量计算得出。

在 precalc 部分定义赋值才有实际意义，因为在计算之后更改变量内容只会导致不一致的结果，且无其他影响。

以下是一个斜齿轮计算的示例文件：

precalc

assert (ZR[0].x.nul < 1)

action msg "Rad 1 的齿廓变位量过大，当前值为 {ZR[0].x.nul}，最大值为 1。已设置为 1."

action set ZR[0].x.nul = 1

assert (ZR[1].x.nul < 1)

action msg "Rad 2 的齿廓变位量过大，当前值为 {ZR[1].x.nul}，最大值为 1。已设置为 1."

action set ZR[1].x.nul = 1

postcalc

assert ((ZP[0].a/ZS.Geo.mn) < 200)

action msg "中心距相对于模数过大 (a={ZP[0].a}, mn={ZS.Geo.mn}, a/mn={ZP[0].a/ZS.Geo.mn})."

说明：

"precalc" 语句打开在计算前必须执行的规则部分。

第一个 "assert" 语句检查齿轮 1 的名义齿廓变位量是否小于 1.0。

如果此 "assert" 不成立，"action msg" 语句将输出提示信息，说明齿廓变位量过大，显示当前值并提示齿廓变位量已设置为 1.0。

"action set" 语句随后将齿廓变位量设置为 1.0。

第二个 "assert" 语句检查齿轮 2 的相同值。

"postcalc" 语句表示在进行计算前要执行的规则集的结束，并打开包含计算后要检查的规则的章节。示例展示了一个 "assert" 语句的定义。该语句检查中心距与模数之间的比率。如果违反了规则，"action msg" 语句将向用户触发提示信息。然而，在计算之后更改这两个值中的任何一个是没有意义的，因此此处没有 "action set" 语句。

公式中允许的运算符和函数（见"计算变量"章）。

规则文件存储在模板目录中（TEMPLATEDIR，通常为“template”子目录，见"目录结构"章）。由于模板目录也可以是项目特定的，因此可以定义项目特定的规则。

English Original

Rules

Rules are used to ensure that in-house guidelines for the ranges of validity of parameters are applied and complied with. This typically concerns the maximum and minimum limits of input values, calculated values and the relationships between these values i.e. length/width ratios, length/diameter relationships or even the relationship between the module and the center distance.

These rules are defined by being stored in a module.rls file, where module stands for the calculation module's in-house label, e.g. Z012 for cylindrical gear pairs.

These rules are subdivided into those that must be fulfilled before the calculation is performed and those that must be checked afterwards. If a rule is infringed, the appropriate messages can be displayed. In the case of rules that must be checked before the calculation, variables can also be set to constant or calculated values.

The following statements are possible:

precalc: marks the beginning of the rules that must be checked before a calculation is performed.

postcalc: marks the beginning of the rules that must be checked after a calculation.

assert(Condition): The condition is ensured. In this case, the condition usually represents a comparison in which both the right-hand and left-hand side of the comparison can also be calculated.

action msg Message: If the condition of the previous assert has not been fulfilled, the message is output. Here the message can include variables, in the same way as report templates.

action set Assignment: If the condition of the previous assert has not been fulfilled, the assignment is performed. The assigned value can be a constant, or can be calculated from variables, in the same way as for the report templates.

Defining an assignment is only really useful in the precalc section because changing the contents of variables after the calculation merely leads to inconsistent results and has no other effects.

Here is an example file for a helical gear calculation:

precalc

assert (ZR[0].x.nul < 1)

action msg "Profilverschiebung Rad 1 zu gross, Ist {ZR[0].x.nul}, Maximum 1. Wird auf 1 gesetzt."

action set ZR[0].x.nul = 1

assert (ZR[1].x.nul < 1)

action msg "Profilverschiebung Rad 2 zu gross, Ist {ZR[1].x.nul}, Maximum 1. Wird auf 1 gesetzt."

action set ZR[1].x.nul = 1

postcalc

assert ((ZP[0].a/ZS.Geo.mn) < 200)

action msg "Center distance too big for module (a={ZP[0].a}, mn={ZS.Geo.mn}, a/mn={ZP[0].a/ZS.Geo.mn})."

Explanations:

The "precalc" statement opens the section of the rules that must be executed before the calculation.

The first "assert" statement checks whether the nominal profile shift of gear 1 is less than 1.0.

If this "assert" is not fulfilled, the "action msg" statement outputs the message that the profile shift is too big, displays the current value and tells you that the profile shift has been set to 1.0.

The "action set" then sets the profile shift to 1.0.

The second "assert" statement checks the same values for gear 2.

The "postcalc" statement signifies the end of the set of rules to be executed before the calculation and opens the section containing the rules that are to be checked after the calculation. The example shows a definition of an "assert" statement. This checks the ratio between the center distance to the module. If the rule is infringed, the "action msg" statement triggers a message to the user. However, there is no point in changing one of these two values after the calculation, and this is why the "action set" statement is not present here.

Permitted operators and functions in the formulae (see chapter Calculation variables).

The file containing the rules is stored in the template directory (TEMPLATEDIR, usually the "template" (see chapter Directory structure) subdirectory). As the template directory can also be project-specific, you can also define project-specific rules.
